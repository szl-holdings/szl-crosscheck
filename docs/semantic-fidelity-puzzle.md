# Source-anchored semantic fidelity for certified puzzle encodings

This bounded, optional Python module addresses a specific limitation in
Sara Behnamian's [*Fair but hard* benchmark](https://github.com/sarabehnamian/Puzzle-generation-with-guaranteed-uniqueness):
two independent encoders can agree on a clue whose **published wording** has
drifted from the generator's intended clue, and the altered puzzle can still
have a unique solution. Solver uniqueness **does not** establish fidelity.

`szl_crosscheck.semantic_fidelity.compare_position_clue` provides a separate,
source-anchored check over a restricted position DSL and the original
per-category all-different base model, using an exhaustive finite oracle.
It deliberately does **not** call a model, execute untrusted Python, authorize
actions, or substitute for the paper's PySAT/CP-SAT uniqueness certificates.

## Synthetic example

```python
from szl_crosscheck.semantic_fidelity import compare_position_clue

report = compare_position_clue(
    houses=5,
    categories={"german": "nationality", "rabbit": "pet"},
    source="Abs(pos('german')-pos('rabbit')) == 2",
    encoder_a="Abs(pos('german')-pos('rabbit')) == 3",
    encoder_b="Abs(pos('rabbit')-pos('german')) == 3",
)
assert report["status"] == "DRIFT"
assert report["dual_equivalent"] is True
assert report["source_equivalent"] is False
assert report["witnesses"]["a_vs_source"]["assignment"]
assert report["uniqueness_certified"] is False
```

The source expression must be independently reviewed for the *exact text
provided to the solving model*, not generated by the same encoders.
Without a source, the status is `INDETERMINATE` even if both encoders agree.
`MATCH` means bounded expression equivalence under the declared base model,
**not** that the source expression accurately translates natural language.

## Scope / limits

- Bounds: 2–6 houses, at most 5 distinct referenced position values, integers
  of magnitude at most 100, expression length at most 2,000 characters.
- DSL subset: `pos('name')`, integer arithmetic `+`/`-`, `Abs`,
  `And`, `Or`, `Not`, `Implies`, and a single comparison per node.
  Unsupported syntax or an impossible base domain raises
  `SemanticInputError`; AST nodes are interpreted, never evaluated with
  Python's `eval`.
- If meanings differ, the report returns a concrete assignment showing the
  disagreement. The assignment is a finite counterexample, not a model score.
- The caller's category map and source expression are **not authenticated**.
  There is no source-byte attestation, unique-solution certificate, runtime
  signer, or evidence of deployment. `execution_authorized` is always false.
- This independent bounded check is not the author's pipeline, nor does it
  claim to replace or reproduce its full position DSL, SAT solver, ladder,
  Python execution environment, or published experimental results.

Run the synthetic checks with `python -m pytest tests/test_semantic_fidelity.py`.
Gate deployment only after the normal repository test and review process.
